# PakScape review — 2026-10-02

Reviewed archive mutations, macOS path registration and imports, clipboard
preflight, and cross-platform demo playback. This is a targeted source review,
not an exhaustive parser audit or interactive desktop sign-off.

## Fixes

- macOS PAK tree construction now merges folder components case-insensitively.
  Previously `Maps/first.bsp` and `maps/second.bsp` created separate folders,
  leaving an archive that could not be saved again.
- macOS PAK and ZIP preflight count implicit folders against the 50,000-node
  limit. ZIP directory entries with nonempty payloads are rejected.
- macOS imports, clipboard copies/moves, and new folders account for destination
  depth before insertion. Directory imports check both files and empty folders,
  accepting the 256-component boundary and rejecting deeper paths.
- Shared C# direct additions enforce entry and payload limits before insertion.
  Moves validate every selected item's parent membership and cross-archive
  capacity before detaching anything, preventing partial removal on failure.
  Bulk directory imports reuse their incremental import budget when constructing
  children, avoiding a full-document scan for every imported file or folder.
- Browser demo playback now builds a PK3 snapshot of the current document on all
  platforms. New documents, macOS ZIP documents, and unsaved map edits accompany
  playback. Companion assets are preserved, unrelated archives are skipped, and
  both expanded payloads and serialized packages must fit the remaining 256 MB
  session budget. Snapshotting does not save or mutate the document.

## Validation

- Shared C# suite: **204 passed**, zero failures or skips, including ten added
  regression cases.
- Linux service suite: **15 passed**, zero failures or skips, including import
  coverage for preserving case-colliding files and folders.
- Both existing native API test executables pass.
- Core, format handlers, Linux services, and both C# test assemblies were compiled
  from current sources with Roslyn and compiler warnings treated as errors.
  The host lacks the complete .NET SDK; the isolated test build reused existing
  dependency DLLs and generated test entry points, targeted .NET 10 references,
  and ran on .NET 10 with major roll-forward for the .NET 8-targeted suite.
- Eight additional Swift tests cover folder casing, implicit-node limits,
  directory payloads, import/paste depth, and current-document demo packages.
- A synthetic Linux import of 3,000 folders with one empty file each took
  **2.51 s** with the first commit's per-child archive scans and **1.17 s** after
  reusing the import budget. These are single local measurements, not a general
  performance guarantee.
- The published demo player's package normalizer accepts `.pk3` packages.
- `git diff --check` passes.
- The first fix commit, `579b1a0`, passed the complete
  [GitHub Actions matrix](https://github.com/timbergeron/PakScape/actions/runs/37037565416):
  macOS Swift tests and app build, Windows build/tests/installer, and both Linux
  architecture builds/tests/packages. The bulk-import follow-up was compiled and
  tested locally and receives a fresh CI run after push.

The local native rebuild was blocked by an existing CMake cache referencing
removed dependency source directories; native code was not changed in this pass,
and CI rebuilt and tested it successfully. No Debian package or interactive UI
validation was performed locally.
