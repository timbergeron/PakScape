# PakScape review — 2026-09-12

Reviewed archive readers and writers, import/export validation, tree editing,
clipboard moves, undo/redo, search, preview routing, native test coverage, and
selected macOS document workflows. This is a targeted source and regression
review, not an exhaustive parser audit or a desktop usability sign-off.

## Changes made

| Area | Finding and resulting behavior |
| --- | --- |
| Archive limits | PAK, PK3, and KPF readers counted stored entries but omitted folders implied by their paths. A small directory table could produce more than 50,000 tree nodes. The Windows/Linux format handlers now count unique folders and files before building the tree. |
| ZIP preflight | PK3/KPF readers decoded each payload before validating later directory entries. They now validate the complete path table and declared expanded sizes before decoding payloads. |
| ZIP directory payloads | Entries such as `maps/` containing file data were silently treated as empty folders. These malformed entries are now rejected instead of losing their payload on save. |
| Import and edit depth | Windows/Linux imports counted depth relative to the source rather than its destination. Imports and direct additions now reject excessive combined depth before modifying the document. Boundary and rollback tests cover files and folders. |
| Clipboard moves | Moving same-named files selected from different folders could rename an item already in the destination, depending on selection order. Existing destination items now reserve their names. |
| Search | Windows/Linux wildcard matching could throw an uncaught regex timeout. Both use a shared wildcard matcher without regex backtracking, preserving `*`, `?`, and case-insensitive matching. |
| Text previews | `.loc` and `.src` were described as text-preview formats but missing from the shared preview extension list. They now open as text. |
| Linux undo/redo | History restoration replaced node identities without clearing the thumbnail cache. It now uses the same cache reset and view refresh as ordinary mutations. |
| Native test coverage | Release builds defined `NDEBUG`, removing audio test assertions and API calls inside them. Assertions now remain enabled. |

The implementation is concentrated in the shared C# archive core and format
handlers, the Windows/Linux import and view-model integrations, and the native
audio test executable. Swift sources were reviewed but not changed.

## Validation

- Shared C# suite: **194 passed**, zero failures or skips.
- Linux-specific suite: **14 passed**, zero failures or skips.
- Native Release suites: **2 passed**, including audio assertions enabled in the
  rebuilt executable. Its imported `__assert_fail` symbol was also checked.
- Shared and Linux test projects build in Release with **zero warnings/errors**.
- An isolated copy of the original source was built with the new archive/edit/
  preview regression tests. **10 tests failed on the original source**; those
  regressions pass with the fixes.
- Three adversarial wildcard patterns reproduced the original regex timeout;
  the replacement returned the expected non-match for each.
- `git diff --check` passes.

The .NET 8-targeted shared suite ran on the available .NET 10 runtime using major
roll-forward. Native .NET 8 execution and Windows GUI validation remain CI checks.
The complete Linux desktop dependency restore could not finish within available
disk space, so the Avalonia app build, Debian packaging check, and interactive
UI checks remain outstanding. Xcode and Swift were unavailable on this Linux
host. In particular, the Linux undo/cache integration was reviewed in source
and still needs an interactive check.

## Recommended next work

These are source findings to reproduce on the relevant desktop before expanding
the changes above.

1. **Apply the same validation rules to macOS.**
   [PakViewModel.swift](../../macos/PakScape/PakViewModel.swift) calls
   `PakLoader.buildTree` with its default depth when importing into an existing
   folder; clipboard `registerTree` also starts at depth one. The destination
   depth is absent from both checks. In
   [PakModels.swift](../../macos/PakScape/PakModels.swift), PAK path registration
   also accumulates implied folders without enforcing their combined count.
   Test nested-destination imports/pastes and PAKs whose implied folders exceed
   the tree limit, then reject them before insertion or tree construction.

2. **Make demo handoff reflect the current document.**
   On macOS, `loadZip` produces a `PakFile` with empty original `data`, while
   `archivePackages(providingMapsFor:)` requires nonempty original data. A ZIP
   archive's custom maps therefore do not accompany the demo. Windows/Linux
   handoff reads the saved archive from disk, so unsaved map edits are omitted.
   Prefer a bounded serialization of the current document, or an explicit save
   step before launch. Cover PK3/KPF, new documents, and modified maps with tests.

3. **Measure large-archive search responsiveness.**
   The Windows/Linux `RebuildCurrentItems` methods synchronously create item
   view models for every descendant before filtering, on each query change.
   Metadata has a cache, but item construction, path generation, sorting, and
   collection notifications still repeat. Measure a 50,000-node archive, then
   consider debouncing queries and constructing view models only for matches.
   This is a performance recommendation, not a measured regression.
